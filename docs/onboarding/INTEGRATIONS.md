# Integrations

No credentials appear here. For every integration the local default is **mock or disabled**: a fresh `.env` from `.env.example` can reach no external service.

| Integration | Direction | Local default | Code |
|---|---|---|---|
| WhatsApp | out (send) + in (webhook) | `MOCK` | `src/integrations/whatsapp/` |
| 99acres | in (webhook) | endpoint refuses traffic until a secret is set | `src/integrations/ninety-nine-acres/`, `src/app/api/integrations/99acres/leads/` |
| Housing.com | in (webhook + file import) | needs no auth by default; callable locally | `src/integrations/housing/` |
| Other portals (OLX, MagicBricks, Meta, Square Connect) | in | skeleton adapters, "awaiting provider access" | `src/integrations/property-portals/` |

| Email | none | not implemented | `SMTP_*` vars unused |
| Redis | infra | optional | `src/lib/rate-limit.ts`, `cache.ts`, `maps-cache.ts`, `notifications.ts` |

## WhatsApp

- **Purpose:** share catalogues, hold per-lead conversations, track delivery status, accept replies.
- **Code:** `src/integrations/whatsapp/` (provider interface in `whatsapp-provider.ts`; implementations `mock-whatsapp-provider.ts`, `click-to-chat-provider.ts`, `meta-whatsapp-provider.ts`; selection in `whatsapp-service.ts#getWhatsAppProvider`; config in `whatsapp-config.ts`; templates and the 24-hour customer-care window in `whatsapp-templates.ts`, `whatsapp-window.ts`; HMAC signature check in `whatsapp-signature.ts`; phone normalisation in `phone.ts`). The older quick-share flow is `src/lib/whatsapp.ts` (`WHATSAPP_API_MODE`).
- **Routes:** `/api/leads/[id]/whatsapp/*`, `/api/whatsapp/inbox/*`, `/api/whatsapp/templates`, `/api/integrations/whatsapp/webhook` (GET verify handshake, POST inbound, idempotent via `IntegrationWebhookEvent`), `/api/system/whatsapp-health`, `/api/system/whatsapp-test-send`.
- **Env:** `WHATSAPP_PROVIDER`, plus five Meta values only for `META_CLOUD` (see [ENVIRONMENT.md](ENVIRONMENT.md)).
- **Local behaviour:** `MOCK` makes zero network calls. Sends resolve instantly; the lead's WhatsApp tab has demo controls to simulate delivered/read/failed and a client reply. `CLICK_TO_CHAT` only builds a `wa.me` link and never reports delivery.
- **Production considerations:** the production template sets the provider for a deliberate employee-click workflow with no automatic sending. Never use `META_CLOUD` or `WHATSAPP_TEST_RECIPIENT` on a laptop: a "test" can message a real person. Setting up Meta is documented in the root `WHATSAPP_SETUP.md`.

## 99acres

- **Purpose:** 99acres POSTs leads to the CRM. The CRM never calls 99acres and never contacts the customer because of a delivery.
- **Endpoint:** `POST /api/integrations/99acres/leads` (`src/app/api/integrations/99acres/leads/route.ts`). Full spec: `docs/99acres-lead-webhook.md`.
- **Architecture:** `HTTPS + per-IP rate limit → bearer auth → 64 KB capped body parse → sanitised raw capture → adapter (alias mapping) → shared portal ingestion (ExternalLeadEvent + Lead) → internal workflows (auto-assign, score, match, automation rules, staff notification)`.
  - Auth: `Authorization: Bearer <secret>`, constant-time compare. Missing/non-Bearer → 401, wrong → 403, **secret not configured → 503 (never open)**.
  - Tenant comes from server config (`ACRES_99_ORGANIZATION_ID`, default `org_default`); nothing in a payload can pick an org.
  - Minimum to create a lead: a valid Indian mobile number. Otherwise the event is stored as `NEEDS_REVIEW` for staff.
  - Idempotent by portal lead id or a payload fingerprint; replays return `duplicate`.
  - Raw payloads are stored sanitised (credential-like keys and any value containing the secret are redacted); visible under **Leads → Portal leads**.
- **Where the secret is configured:** the `ACRES_99_WEBHOOK_SECRET` variable, read only in `src/integrations/ninety-nine-acres/config.ts`. In production it lives in the server's private env file (generated by `deploy/scripts/02-gen-env.sh` on a fresh install). It is **not** in the repo, not in this document, and you do not need it. Rotation is an operator task: edit the server env file, restart the app, tell 99acres the new value. The previous mock route `/api/integrations/leads/99acres` was removed because it was open when its key was unset.
- **Local testing:** put any throwaway random string in your own `.env` as `ACRES_99_WEBHOOK_SECRET`, restart `npm run dev`, then `curl -X POST http://localhost:3000/api/integrations/99acres/leads -H "Authorization: Bearer <your throwaway>" -H "Content-Type: application/json" -d '{"name":"Test Person","phone":"9000000000"}'` (the number must be a plausible but **fake** Indian mobile; never real customer data). Unit tests live beside the route (`route.test.ts`, `no-unauthenticated-ingestion.test.ts`).
- **Without a secret:** the endpoint returns 503. That is correct, not a bug.

## Housing.com, MagicBricks, OLX, Meta

- **Housing:** `POST /api/integrations/housing/leads` (inbound; spec in `docs/housing-lead-webhook.md`; optional `HOUSING_WEBHOOK_SECRET` / `HOUSING_ALLOWED_IPS`) and a spreadsheet lead importer at `/integrations/property-portals/housing-import` (`/api/imports/housing/*`).
- **Generic portal webhook:** `/api/integrations/property-portals/[provider]/webhook`, admin-configured connections (`PropertyPortalConnection`), listing mapping and retryable operations. Architecture and the provider capability matrix: `docs/portal-integrations.md`. OLX, MagicBricks, Meta and Other are "awaiting provider access": adapters are skeletons that must use official contracts only (no scraping).
- **MagicBricks mock:** `POST /api/integrations/leads/magicbricks` requires `MAGICBRICKS_API_KEY` in `x-api-key`; unset ⇒ 503.
- **OLX** exists as a lead *source* (forms, filters, scoring, assignment rules) regardless of any API integration. Staff can enter OLX leads manually today.

## Maps

- **Purpose:** geocoding, autocomplete, directions, embedded preview.
- **Code:** `src/integrations/maps/` (`maps-service.ts`, `google-maps-provider.ts`, `disabled-maps-provider.ts`), caches in `lib/maps-cache.ts`. Routes: `/api/maps/autocomplete`, `/api/maps/geocode`, `/api/properties/[id]/geocode`, `/api/system/maps-health`, `/api/system/maps-capabilities`.
- **Env:** `MAPS_PROVIDER` (`DISABLED` default | `GOOGLE`), `GOOGLE_MAPS_SERVER_API_KEY`, `NEXT_PUBLIC_GOOGLE_MAPS_BROWSER_API_KEY`.
- **Local:** keep `DISABLED`. Manual address entry, GPS capture, the nearby-properties radius search and "Open in Google Maps" links need no key. Setup of the real thing: root `GOOGLE_MAPS_SETUP.md`.
- **Production:** keys are domain/API-restricted; per-endpoint rate limits protect quota.

## Object storage

- **Purpose:** property images and documents. Uploads are presigned direct-to-bucket (browser PUT to R2) or server-mediated depending on provider; objects are private and served by short-lived signed URLs. Object keys contain no personal data.
- **Code:** `src/lib/storage.ts` dispatches to `src/lib/storage-providers/{r2,s3,firebase,disabled,mock}.ts`; images in `lib/property-images.ts`; routes under `/api/properties/[id]/media/*`, `/api/documents/*`, `/api/property-images/*`, `/api/system/storage-*`.
- **Env:** `STORAGE_PROVIDER` (`DISABLED` default), `R2_*`. Details in [ENVIRONMENT.md](ENVIRONMENT.md).
- **Local:** `DISABLED`: upload endpoints answer a clear 503 and every other page works; seeded demo properties use metadata only. If you must test uploads, run the MinIO container from `docker-compose.yml` and use `STORAGE_PROVIDER=S3` with a throwaway bucket.
- **Production:** Cloudflare R2. The non-secret `R2_*` values are baked into the Content-Security-Policy at image build time (`src/lib/csp.ts`), so changing bucket or domain needs a rebuild and a bucket CORS update.

## Email

Not implemented. `SMTP_HOST` and `EMAIL_FROM` are validated if present but no code path sends email. Password setup/reset links are generated for an admin to deliver (for example over WhatsApp), not emailed.

## Redis

- **Purpose:** rate limiting (`checkRateLimit`), read-through caches for dashboards/reports, maps cache, and a lock that stops overlapping notification sweeps. **No business data.**
- **Local:** `docker compose up -d` provides it on port 6380; set `REDIS_URL` or leave it unset.
- **Failure mode:** every use fails open with short connect/command timeouts, so a Redis outage degrades to "no rate limiting / no cache", not downtime.
- **Production:** password-protected container on an internal-only Docker network with a 128 MB LRU cap and AOF persistence.

## Scheduled work

`GET`/`POST /api/internal/notifications/sweep` (bearer `CRON_SECRET`) creates due/overdue follow-up notifications. Production host cron calls it nightly; `vercel.json` still declares the equivalent Vercel cron. Locally nothing runs it; to try it, set `CRON_SECRET` in your `.env` and call it with `curl`.
